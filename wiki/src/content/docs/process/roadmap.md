2026-09-21 · 执行计划 v1。各阶段均为后续工作；本页不把计划写成已完成成果。

后续按整包里程碑推进。当前主线是把归航号的总体、舰内生活、生存生产、港口和三类舰载机体设计完整；随后用 Blender 和 Unity 验证，再制作完成品质的首章，并据此扩展正式游戏。

## 当前起点

归航号已经有持续生活与探索的使命、工业舰船视觉身份、母舰与三类机体的早期手稿、三处生活场景，以及 N48 邻里平剖和空间研究。现阶段缺的是彼此一致的全舰总体：人口与保障目标、居住重力架构、机体编成、统一尺度与接口还未共同收敛。

48 人是一个邻里样本；2400 米舰长、千人容量、原机体尺寸、纪元和推进能力均仍是候选。总体方案应重新核算这些量的关系，再决定保留哪些。

Unity 已有首航、建设、教学、奖励、存档和文字剧情的原型与历史验证记录。后续在这个工程上接入新资产与玩法，不从零重做；历史测试不直接证明新布局、新模型和新流程可用。

## 母舰概念总包：九组工作一次列全

| 工作组 | 本次主线必须覆盖的设计 | 可以收口进入下一步的证据 |
| --- | --- | --- |
| **1 总体与统一尺度** | 清醒/休眠/成长容量；社区层级；生活、工业、仓储、港区、动力、保全的分区；正常与受损状态；维护余量 | 舰体—机体—门口—人员共用标尺；主要平剖与分配表相互对应 |
| **2 住舱与日常** | 单人、双人、家庭舱的私密、储物、卫浴、隔声和轮班；餐厅、洗衣、照护；24席日常与48席聚餐布置；适合不同身体条件的居住选择 | 一套完整邻里中的睡觉、洗澡、换衣、搬运、用餐和照护动作有明确空间，待测净空可定位 |
| **3 文明公共生活** | 议事、学习传承、运动休闲、文化档案、纪念、接待；不同年龄的生活；共享医疗与康复 | 区分邻里设施与全舰共享设施；居民到得了，日常和集会两种状态都能使用 |
| **4 生存与生产** | 水、空气、食物、废物、能源和散热关系；培养、种源、病害处理；工场、有限制造、工具、备件与仓储；休眠保全 | 重要物资有来源、处理、储存、消耗、回收和损耗去向；依赖外出采集或交换的部分明确 |
| **5 交通、重力与压力** | 旋转段交通环与固定轴接口；人员、货物、担架、机体路线；楼梯、升降、低重力作业和分区关闭 | 从住舱到舰桥、港口的转换节点齐全；支承和旋转扫掠不占港区；替代路线有去处 |
| **6 双港与作业保障** | 出击、捕获、等待、横移、卸料、样本检查、伤机隔离、维修和再出发；门叶侧剖、驱动和收纳腔 | 正常返航与受损返航两套完整动作，三类机体都有停放、转运和维修位置 |
| **7 三类舰载机体** | 探索、战斗、采集各自的任务与代价；操纵/乘员方式、载荷、多视图、收纳/展开、故障回收、维护和共用接口 | 每类完成一项代表任务并回到母舰；轮廓、设备和动作能说明用途；接口与港区对得上 |
| **8 外观与视觉身份** | 主轮廓、六视图、剖切、远中近观察；双港、居住结构、维护面、通信、散热与推进部件；全舰内外材料和标识 | 同一部件的数量、位置和尺度一致；外形解释内部，保留厚重而有美感的工业科幻风格 |
| **9 拆解与制作交接** | 外壳—骨架—舱段—设备层级；门、转运车、旋转支承和机体关节；工具入口、拆卸方向、换件路线及版本编号 | 拆解部件能回到装配图；可动/固定/可拆对象明确；维修动作有空间，问题能直接交给白模验证 |

每组按需要组合生活主景、同尺度平剖、关键细节、动作序列和拆解图。交付量由这些关系是否成立决定；把一张图拆成多张不计作里程碑进展。

## 先解决三个会引发全船返工的决定

1. **维持怎样规模的持续生活社区。** 比较清醒人口、休眠保全、家庭与轮班、共享服务和有限生产能力，提出推荐工作规模。N48 用作局部样本，不直接倍乘成全舰人口。
2. **居住重力与交通采用什么架构。** 确定旋转段的位置、轴向、半径候选与固定部分的连接方法，再深化受曲率影响的住舱和总体外形。
3. **保障怎样的外出编成。** 联合确定探索、战斗、采集的编成、任务周期、最大收纳和受损回收包络，让港口、工场与储备围绕真实用途安排。

科技纪元需要同时落实为可用的能力边界：推进、能源、材料、感知、通信、医疗、自动化和制造各自能做什么、代价是什么、哪些仍依赖外界。它必须能支持上述三个决定和首章事件；剩余宇宙设定按故事需要继续展开。

## 并行方式与范围控制

M1 收敛共同约束后，生活与公共空间、生存生产、港口与机体、外观与视觉规范四条工作线并行。根任务维护唯一尺度表、接口表和选定版本，在每个里程碑进行跨组评审。

设计完整性和制作深度分开安排。全舰主要功能需要在总图中交代，但首章真正可见、可进入、可交互的区域优先做精；后台设施先做到布局、接口和运行关系清楚。每条线都使用“居民的一天、一次远征、一次故障”校核自己的设计。

剧情和角色写作、UI规范和声音方向可以提前并行；正式片头继续按**世界观稿 → 运镜脚本 → 关键帧 → Blender预演 → 经验证的视频生成流程 → 剪辑、声音、Unity接入**推进。素材须通过实际观看和游戏内播放检查，保留生成输入及版本。

首章沿用单人、单航区的工程基础。探索与采集先形成完整循环，战斗在有真实目标、操作反馈和回港结果后按进度接入；三类机体的完整概念设计仍属于当前母舰总包。首章时长、舰内交互视角、目标设备与性能预算在 M1/M5 对应任务书中明确，不在没有测量时承诺工期或帧率。

## 每个里程碑怎样交付

每包一次交齐：设计说明、选定图稿、统一尺寸/接口、实际提示词与参考链、初版与返修对照、评审结果和剩余问题。Wiki 作为可持续阅读的制作档案，浅色界面与逐图提示词要求持续保持。

推进状态区分“待设计、设计中、待核对、可进入白模、模型验证、已进引擎、原生验收”。自行图面复核不代替用户的审美反馈，局部通过不提升为全舰或成品通过。

常规布局取舍、补图、修图和验证由制作侧持续完成；会推翻已认可方向、显著扩大范围或新增外部支出的决定集中说明。阶段内持续工作，汇报真正的取舍和问题，不在每一两张图后把推进责任交回用户。
