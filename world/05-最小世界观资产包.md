# 群星回响 · 最小世界观资产包

2026-09-21 · 参考 内部参考项目 七层框架后的第一组制作资产。

用途：让新接手的文案、美术和实现者可以直接作出具体决定。它补充[世界设定集](02-世界设定集.md)，不创建新的运行时规则。状态一律分开记录：**创作地位**（现有正典／本轮设计基线／候选／退役）、**实现状态**（已实现／待制作）、**揭示范围**（直说／体验后揭示／作者侧）。本轮设计基线来自当前设计任务，允许继续本地制作，不冒称已获团队正式拍板。

## A. 主题与关系依据

**SE-THEME-01｜没有预定归宿时，怎样通过共同生活、认识未知与相互托付，形成继续存在的理由。**

现行主题依据为用户已接受的[使命与生活基线](11-归航号使命与生活设计基线.md)；旧主题“把陌生远方变成可负责任抵达与归来的地方”保留为其中一条关系表达。归航号是无可依赖母港的独立文明家园，劳动改变生活，远行有可理解的代价，失败留有恢复路径；好奇心也能使无物资收获的发现值得。活下去 → 值得生活 → 选择如何存在是创作弧线，不新增意义分数、唯一真理或未经设计的结局。

稳定是有效成果，不能固定用灾难驱赶已安顿好的玩家；停留、定居与远行均须获得真实理由。持续清醒班底与关系连续性优先，休眠不能注销已经发生的劳动、选择和人物经历。以上为新增设计约束，不改现有资源、人口、岗位、休眠或存档规则。

**SE-REL-01｜为什么玩家能够介入这个世界。**【本轮设计基线／待制作／分层揭示】

- 玩家与其他六位初醒者共同承担本次航程；舰长拥有航行与资源安排职责，专业人员负责报告条件并执行可行工作。舰长的指挥权有能力边界，不能让一个岗位同时做两件事，也不能决定过去已经发生了什么。
- 方舟与旧站之间共享历史接口标准。现场确认、修复与接管使玩家获得设施服务，不使玩家获得对一切陌生生命的所有权。
- 这份关系同时带来收益与负担：船员让远征成为可能，苏醒增加岗位，也增加照管需求；旧站留下物资，也留下待验证的记录和维护责任。
- 关系暂时中断时，先遣艇可以返航或求援，当前游戏没有人口死亡；暂停和离线冻结模拟。不能用掉线、退出游戏或未读通讯处罚玩家。

内部产品 的“连接神话”在本作转化为这组职责、技术兼容与接续关系。不会给舰长添加神秘身体共振来解释现有经营操作。

### 三项基础约束及裁决

| ID | 基础约束 | 可直接裁决的设计问题 |
| --- | --- | --- |
| SE-LAW-01 | 有用的东西需要来源、处理和运输；改进可以降低代价，不能无声取消代价 | 旧站现货不能因反复扫描再生；后来若增加可靠远程数据传输，需明示新能力、范围和解锁条件，首章仍按现行星图运输规则 |
| SE-LAW-02 | 过去留下的记录与此刻得到的证据是两类信息 | 历史接替请求不能变成当前限时求救；一句“没有回答”不能推断全人类灭绝 |
| SE-LAW-03 | 成长必须留下真实且可追溯的结果，具体表现不能冒充模拟事实 | 未建模块不进开场船体；待机模块不表现生产收益；角色只能记得已发生的事件，新版本不借一句“幻觉”注销玩家之前的航程 |

以上与世界设定集 W01—W08 对应，是用于决策的短版；八条详细规则保留。主题不禁止资源栏、教程奖励、主动调度或清楚的系统提示。

方舟总体按[持续生活使命](11-归航号使命与生活设计基线.md)重审；[07](07-科技纪元与方舟设计依据.md)的旧休眠迁徙主使命已被替代，技术数字仍待复评。“未建模块不进开场”约束尚未获得的升级，不否定基础能源、生活与保全设施。生活、医疗、培养、工场与公共空间应支持持续使用，休眠不再是唯一主载荷。任务书须区分现有、封存待恢复与未来增建；新的舱室需求尚未实装。

## C. 可写作的角色卡

以下是作者与后续内容生成可以消费的卡片格式，不是已加入存档的新字段。静态身份来自现有正典；偏好深化为本轮设计基线；动态输入必须从真实状态取得，不能让文案自己生成库存、关系分数或人生经历。

| 字段 | SE-CHAR-CEN｜岑宁 | SE-CHAR-LIN｜林芽 | SE-CHAR-WEN｜闻舟 |
| --- | --- | --- | --- |
| 静态身份 | 轮机长，开局已醒 | 生态师，开局已醒 | 通讯员，新住舱后苏醒 |
| 最先注意 | 接口、残油、噪声与返航条件 | 食物、种源的用途、同伴的生活 | 信息来自谁、何时形成、证实到哪里 |
| 私人愿望 | 放下工具吃完一顿热饭 | 让饭桌有一种大家喜欢的味道 | 得到一份确实来自现在的回应 |
| 盲点 | 容易把疲劳藏进维护清单 | 对保留种源投入过多期望 | 谨慎可能延迟合理行动，也可能太希望听到回应 |
| 行动偏好 | 先检查并提出最小修复方案 | 先辨认能保留什么、怎样继续生长 | 先说明来源与不确定性，再提出验证办法 |
| 动态输入 | 当前停泊、循环舱是否实际运行、真实归航结果 | 温室是否接管、实际带回什么、当前苏醒人数 | 住舱是否已建、知识是否送回、阵列是否存在、决议是否已记录 |
| 经历输入 | 已发现的 `life/home/network`；不得凭排序补造经历 | 已发现的 `home/garden/waking` 及可靠事件；她不会知道尚未拿到的种源签 | 已发现的 `waking/archive/signal/departure`；未苏醒时禁止出场 |
| 关系表现 | 关心通过为人留泊位、接驳和提醒余量表达 | 记得餐桌与别人想吃的东西，允许对工程意见提出异议 | 感谢照管，愿意共享判断，绝不假装拥有全知视角 |
| 语言动作 | 具体工作开头，简短收束，不反复喊“舰长真伟大” | 从一件生活物或实际观察开头，不每句都用植物比喻 | 把事实与推测分句说清；不把“可能”说成“发现” |
| 不能发生 | 未发生救援却回忆救援；未运行循环却说耗材已减少 | 温室只接管未带货却说饭已做好；新住舱前说九个人围桌 | 在开场播音；将灯海旧录音说成刚收到的人声；替舰长作出广播决定 |

**经历怎样改变后续反应：** 首次货物归航可以出现较完整的关切与生活愿望；之后同类成功返航改为简短确认。发生救援后可以提到遗留箱与安全归来，只有真实回收后才庆祝货物找回。变化依据实际事件，而非累计“好感度”；相关精细事件选择仍待实现。

**分化判据：** 同一场景换两张卡，观察对象、提出的行动或对后果的关注至少有一项不同；去掉姓名仍能解释差异来自卡片哪一条。只换口癖、同说一句抽象鼓励不算通过。三人也可以得出同一个安全结论，不能为区分强造不合理争吵。

## D. 最小表达规范

系统说明负责精确操作，人物表达负责立场与感受。系统可以写“领取预备储备”“货物已入库”；人物不用“任务完成+30”评价对方的生活。不能因追求诗意而隐藏燃料、人手和返港条件。

| 时刻 | 合格表达方向 | 拒绝原因 |
| --- | --- | --- |
| 只有待办、尚未完成 | “接驳还没有恢复，需要艇上保留一件构件。” | 不把计划写成成果 |
| 循环舱建成但待机 | “舱段已接好，当前尚未运行。”只有确认缺岗位时才补充岗位提示；缺电、主动停机与休眠按真实原因解释 | 不把所有待机归因于缺人，也不播放只有运行后才成立的减耗庆祝 |
| 无货返港 | 先确认人和艇安全；若有真实观察或经历，可表达其独立价值；下一趟由真实条件决定 | 不说满载而归，不嘲讽白跑，也不能捏造发现或偷偷发放未发生的资源奖励 |
| 没有实时回应 | “这段是旧档案；现在有没有人，我们还不知道。” | 不制造虚假的求救倒计时 |
| 读取失败 | 清楚说明记录无法读取并保留返回入口 | 不用无法理解的世界黑话隐藏错误，也不把故障编成船员死亡 |

建议短通讯只承担一个事实或一种反应，约一至三句。关键机制用准确重复保证理解；人物关系用变化而非长篇重复推进。这是写作约束，不是机械字符截断规则。

现有正典不能被新镜头或新文案无意改写；若确实改变方向，应明确记录旧说法、新说法、理由、受影响资产与存档语义。开发别名不需要一律补写成复杂世界历史。
