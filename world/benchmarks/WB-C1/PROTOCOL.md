## 0. 用途、轨道与保密状态

本协议评测一份**冻结版本**的世界设定集文档，并判断三件事：
- 文本是否满足已选方向的必要条件；
- 文本能否支撑多人继续创作；
- 哪些问题需要改稿，哪些只能承认证据不足。

本协议不含任何对原稿的判断。第 3、4 节中凡涉及具体条目的步骤，均须在原稿冻结后执行。

**两条轨道，结论互不替代**

| 轨道 | 执行者 | 可得结论 | 不可得结论 |
|---|---|---|---|
| 文档审查轨（D 轨，本轮可执行） | 不同模型家族的独立会话；协调人可以是人或模型 | 文本内部一致、约束可查、方向必要条件是否写出 | 真人是否觉得恢弘、神秘、动人；游戏是否好玩 |
| 真人审读轨（H 轨，以后执行） | 已确认到场的真人：叙事设计者 1 名、项目外读者 1 名 | 真人读文档时的吸引力意见；抽查 D 轨记录 | 玩家体验。这需要原型与玩家测试，两轨都不能替代 |

**身份记录**
- 每个执行者都按真实情况登记（登记字段见 5.4）。
- 不得把模型登记为真人，也不得把 D 轨结论写成真人意见或读者测试。

**保密状态**
- 本协议全文（含第 5 节校准材料和第 6 节留出变体）已被当前协调者看到，不宣称对协调者或外界保密。隔离只针对后续评委，规则见 5.3。
- 协调者因此不得担任评委。

## 1. 对象、质量与证据

### 1.1 对象与不可推出的结论

**对象**：冻结版本的全文，记录版本号、SHA-256 和条目数。作者口头说明、聊天记录和草稿都不算对象。

**版本哈希的定义**
- 协调人把冻结版本导出为**单一 UTF-8 文件**：换行统一为 LF；无 BOM；不做其他规范化。
- 该文件存档。版本哈希 = 对该文件全部字节计算的 SHA-256。
- 多文件原稿须先按声明顺序拼接成这个单一文件，拼接顺序一并存档。拼接方法〔ED23〕：每个文件只做上述两项规范化（去 BOM；换行统一为 LF，CRLF 与孤立 CR 都视为换行），不改动其他字节；然后按声明顺序相接，相邻两个文件之间插入恰好一个 LF。

**本轮不能推出**：
- 可玩性、实际吸引力、玩家牵挂；
- 物理和工程可行性；
- 与其他作品的优劣；
- 分支实现后的一致性；
- 作者能力。

"放行"只表示可以继续创作，不等于作品优秀。

### 1.2 维度与题目

每题只属于一个维度。

| 维度 | 内容 | 题目 |
|---|---|---|
| D1 | 法则、历史、关系、数值的内部一致 | T01、T12 |
| D2 | 突破清楚，代价可理解 | T02 |
| D3 | 入侵有限，本地力量有抵抗 | T03 |
| D4 | 留下与远行各有价值，不靠反复灾难驱动迁移 | T04 |
| D5 | 母舰既是武装平台，也是家园 | T05 |
| D6 | 社会成因多元，文明不按物种划分善恶 | T06、T07 |
| D7 | 生活牵挂（仅检查文本可审部分） | T09 |
| D8 | 神秘与探索：留白有边界，地点各有独特性 | T08、T13 |
| D9 | 协作可用 | T10、T11 |

### 1.3 证据等级

- **E1 直接文本**：给出条目 ID 和原句。
- **E2 合法推导**：前提全为 E1，推理不超过两步，推理链写明。
  - 允许单前提推导：一条 E1 写明的一般规则，直接适用到文本已点名的对象。
  - 使用常识须标注"常识"，且常识不得引入数值或动机。
- **E3 评委补写**：需要新事件、新动机、新数值才能成立的内容。E3 只能写入"改稿建议"栏。
  - E3 不能使任何子问成为"有据"。
  - 出现 E3 本身不构成失败。某子问只有 E3 可用时：规定检索（2.5）已完成 → 记"缺失"；检索未完成 → 记"未检"。
- **E0 合法留白**，属于以下两种之一：
  - 文本明确标注未定、保留或交给后续作者；
  - 文档未承诺的工程参数和数值精度，如能耗、航速、质量。
- **A-note 作者说明**：只做记录，写入下一版本前不算证据。

### 1.4 叙述分层（处理"不可靠叙述"）

每条事实陈述按 E1 可查的标记归层：
- **作者层**：以设定口吻陈述，或文档注明为正典/事实的内容。
- **记录层**：文内档案、史料、传说，须有"据某某记载"、条目类型为文献等明确标记。
- **叙述者层**：注明为某角色或派系所知、所说、所信的内容。

没有标记的一律归作者层。发现冲突时按下表处理：

| 情形 | 判定 |
|---|---|
| 冲突双方都在作者层 | F1。全卷通用的"本书部分内容不可靠"类声明不豁免 |
| 一方在记录层或叙述者层，且作者层给出真相或标明未决 | 不算矛盾 |
| 一方在记录层或叙述者层，但作者层沉默 | 记"层级未决"，按局部缺口处理，不判 F1 |

评委不得补写"某人为何撒谎、为何记错"；这类内容属于 E3。

### 1.5 反填充规则

1. **有效内容以是否含约束或后果判断，不看载体。** 流程、列表、表格只要写明限制了谁、改变了什么、允许什么、与谁冲突，就是有效证据。
2. **以下内容只用于定位，不作证据**：只有名称、没有约束的索引；"可按需调整"一类表述，除非同时写明其中哪些是固定的；免责说明。
3. **悬空率**（每轮各算一次）
   - **专名清单**〔ED19〕：专名指文本为本世界新造或专指的名称（人物、地点、组织、制度、物种、技术、事件等），别名表中的同一对象合为一个。专名的首次定义位置 = 全文按条目顺序第一次出现该专名或其别名的条目。协调人在每轮 S1 列出首次定义位置位于本轮样本条目内的专名，冻结后下发评委。识别基准：别名表登记的全部主专名与别名必收；协调人另加的新造名逐条附首次定义条目 ID 与原句。专名清单连同列表者身份存档，列入 3.4 的复现输入。
   - **分母**：本轮专名清单的专名数。分母为 0 时，本轮悬空率记"不适用"。
   - **后果句搜索**：对每个专名按 2.5 检索（搜索名 `DANGLE/<专名>`，<专名> 取别名表登记的主专名，未登记的取清单所附原句中的写法〔ED7〕）。全部命中条目读完仍无后果句 → 悬空；预算用尽仍未读完 → 未定；读到后果句 → 非悬空。
   - **评委间合成**〔ED19〕：每名有效评委逐个专名登记"悬空 / 非悬空 / 未定"。协调人对每个专名取过半数有效评委一致的登记；没有过半数一致时记"未定"。
   - **报告区间**：下限 = 悬空数 ÷ 分母；上限 =（悬空数 + 未定数）÷ 分母。两轮分别报告。
   - **阈值**〔ED19〕：取两轮下限中的较大者（"不适用"的轮次不参与）；它超过 30% 才触发 2.7 的定点改稿。两轮都不适用时不触发。这个阈值是对样本统计量设的初始约定，不是全文结论。
4. **理由禁用词。** 判定理由不得以"丰富、体量大、术语完整"或复述作者术语为依据；出现即退回重写。
5. **记录与展示分开。** 记录表逐子问保存全部依据，不设上限；报告中每个题目实例最多展示 3 条代表引文。
6. **相关性检查**：只检查每条引文是否陈述了它所支持的那个子命题，或是否是该推导的前提。有其他独立佐证不构成作废理由。

## 2. 判定

### 2.1 子问状态

每个子问登记为以下五种状态之一：
- **有据**：有 E1 或 E2 支持。评委的推断、补全或新设定都不算有据；评委不得创造新的世界事实。
- **留白**：属于 E0。只允许非★子问登记留白；★子问不接受留白，查完仍为 E0 时登记为"缺失"。3.3 专用规则指定为"无可查对象"的非★子问（T01 引用条目为 0）也登记为留白〔ED16〕。
- **缺失**（v1.2 称"已查缺失"）：完成规定检索（2.5，★与非★子问同一范围）后仍无 E1 或 E2 支持，只能靠 E3 回答。这是文本发现，不是证据不足。
- **层级未决**：见 1.4。
- **未检**：因实例不足，或规定检索未完成，而无法作答。

### 2.2 题目实例判定

**输入**：2.2 的输入是经 5.5 合并后的实例登记，即每个子问一个状态，以及已确认的失败事实与封顶条款。单个评委的登记在合并确认前不算确认〔ED20〕。 代码登记约定：`judgment.judge_instance` 只接收合并后的一份登记；硬失败代码与专用失败条款由调用方登记，缺失的★子问由代码导出；封顶类条款按 `judgment.CAP_CLAUSES` 中的登记名登记，题号或条款名不匹配时代码拒绝判定。

**先登记失败事实。** 对每个题目实例，以下三类登记为失败事实，每项须附定位：
1. 经 5.5 合并确认的硬失败代码（2.4）；
2. 缺失的★子问；
3. 已被触发且确认成立的专用失败条款：T06"全部由资源导出"、T13 对照不成立（全部同质）。

失败事实只能由 5.5 的遗留核查、R3 裁定，或 5.4 经协调人核实的 D 轨记录更正撤销。其他子问的状态不能使其消失。

**专用条款分两类**〔ED2〕：
- **失败事实类**：T06"全部由资源导出"、T13 全部同质，以及 F4b、F4c（属硬失败代码 F4）。按上条登记为失败事实。
- **封顶类**：T04 F4a 风险筛查、T08 模糊无界超过半数、T10 未标明超过半数、T11 遗漏 T01 的法则。它们在第 4 步之后施加（只有这四题有封顶类条款，T09 没有），使该实例最高为有条件通过；封顶不能提高档位。

专用条款只在其列明的触发条件成立时生效；不成立时，其子问回到第 2 步和第 4 步的通用规则处理，不得以"本题有专用判据"为由判无档。

**再按顺序取第一条符合的：**

1. **存在失败事实 → 失败。** 已证实失败优先于一切未检；其余未检子问写入附注。
2. **任一★子问未检 → 证据不足。**
3. **T09 按专用计数判定**（三问为完整计数规则，层级未决不计入有据数），结果受第 5 步封顶（T09 没有封顶类条款）：
   - 有据数 ≥ 2 → 通过。第三问为缺失或未检均不影响结果；若为未检，须注明。
   - 有据数 = 1，且其余两问均已查完（不是未检）→ 有条件通过。
   - 有据数 = 0，且三问均已查完 → 失败。
   - 其余情形 → 证据不足。
4. **通用规则**，适用于除 T09 外的所有题，以及未被触发的专用条款：
   - 任一子问（含★子问）为层级未决，或任一非★子问为缺失 → 有条件通过〔ED3〕。
   - 任一非★子问未检，且没有子问为缺失或层级未决 → 有条件通过〔ED3〕；未触发封顶类条款时，标注"含未检非★，上限可能为通过"。
   - 全部为有据或留白 → 通过（非★留白不降档〔ED1〕）。
   - 触发了封顶类专用条款的，档位最高为有条件通过。
5. **层级未决封顶**：任何题只要存在层级未决，最高只能判有条件通过。专用条款和 T09 计数都不能突破此封顶。

**题目档位**
- 同一题有多个实例时，取最差档。严重程度顺序为：失败 > 证据不足 > 有条件通过 > 通过。
- 题目没有可判实例时（3.3 把该题记为未检：m = 0 且不属于或未完成 F0 检索、成对题不足、T12 两部分都没有可判内容），题目档位为**证据不足**，并注明原因〔ED4〕。
- F0 成立时，F0 作为失败事实登记到 2.5 映射表所列的题目上，该题档位为失败〔ED5〕。

### 2.3 维度合成

维度下各题中：
1. 有任一失败 → 维度失败；
2. 否则有任一证据不足 → 维度证据不足；
3. 否则有任一有条件通过 → 维度有条件通过；
4. 否则 → 维度通过。

题目只产出题目档位；维度判定只由本规则产生。跨轮合成见 5.5。

### 2.4 硬失败代码

| 代码 | 条件 |
|---|---|
| F0 | 必需类别（除"分支""人物"外全部类别）在抽样框中为空，且完成负证据搜索后仍无相应内容（判定细则见 2.5） |
| F1 | 作者层内出现直接矛盾，文本没有解释 |
| F2 | 突破类技术没有写代价，或代价只有形容词 |
| F3 | E1 把入侵写成不可抵抗的全面毁灭；或完成负证据搜索后，没有任何具体抵抗行动 |
| F4 | F4b、F4c，见 T04（F4a 只是风险筛查，不是硬失败） |
| F5 | E1 把某物种或文明整体定为善或恶，且完成负证据搜索后，没有任何内部差异 |
| F6 | 完成负证据搜索后，母舰居民没有任何日常语境 |
| F7 | 作者层内，对同一对象、同一时间或分支作用域，同时存在"固定"与"可分化"两种 E1 表述，且文本没有解释 |

**判 F7 前**，协调人须机械核对三项并记录：两条原句都存在；两条都属作者层；作用域相同。**评委分歧不是 F7**：两名评委对"固定/可分化"判定相反，属于评委分歧，按 5.5 处理，不是世界文本的矛盾。

### 2.5 规定检索（子问缺失、F0、F3、F5、F6 与悬空的前提）

**搜索名与阅读顺序**〔ED7〕
- 每项检索有一个搜索名：
  - 子问检索：`<题号>/<实例ID>/<子问名>`，例如 `T02/E0042/代价是什么`。子问名 = 第 4 节该子问的原文去掉行首★、括注与末尾问号；成对实例（T03、T13）与 T10 的实例 ID = 各条目 ID 按码点顺序以 `+` 相接；T04 普查实例 ID 为 `普查`，T08 为 `台账`，T12 数值部分为 `数值`〔ED24〕；
  - T13 地点检索：`T13/<实例ID>/<地点条目ID>`；
  - F0 检索：`F0/<类别>`；
  - F3、F5、F6 检索：`F3/<入侵方主专名>`、`F5/<文明主专名>`、`F6/<母舰主专名>`；
  - 悬空检索：`DANGLE/<专名>`。
- 先求出规定范围内的全部条目并去重。子问检索与 T13 地点检索先读实例条目本身（多条时按 ID 码点顺序）；其余条目按 key("N|"+搜索名, 条目ID) 升序阅读，即按 SHA-256(种子|N|搜索名|条目ID) 升序。
- 阅读单位是条目：读一个条目就是读它的全部正文，同一条目内的多处命中按原文顺序读。

**预算与结论**
- **阅读预算**：默认每项检索 150 个条目（原文"150 处"，"处"指去重后的条目；实例条目本身计入〔ED8〕），S1 时可调整。预算须在公布种子前冻结。

## 3. 抽样与实例选择（确定性）

### 3.1 抽样框、别名表、引用表与搜索键

**条目单位**〔ED12〕
- 标题行按下面的字面规则判定（取自 CommonMark ATX 标题，但以本条为准）：行首第 0 列起连续 1—6 个 `#`，其后是一个空格或行尾；行首有空格的不算；标题文字 = 该空格之后到行尾的全部文字，不剔除尾部的 `#`。围栏代码块指从一行以三个及以上 `` ` `` 或 `~` 开头的行起、到下一行以同样字符开头的行止（含两端），未闭合的延至文末；块内的行不算标题行。其他标题语法（如下划线式）在导出前由协调人改写为 ATX，改写记录存档。
- 每个标题行开启一个条目。条目正文是该标题行到下一个标题行之间的内容。本节的"正文"指去掉空行（只含空白字符的行）后仍非空的内容；"没有正文"即去空行后为空，E0000 的"非空"同此。父标题自身的正文属于父标题条目。
- 没有正文、但有下级标题的标题不成条目，它的标题文字作为路径记入下级条目。
- 既没有正文、也没有下级标题的标题（空叶标题）不成条目。它的标题文字作为附注记入前一条目，供检索与定位使用；文档开头的空叶标题记入其后第一个条目。
- 第一个标题之前的非空正文记为条目 E0000"前言"。
- 条目 ID 一律由协调人按出现顺序编为 E0001、E0002……；文档自带的条目编号作为别名登记入别名表。条目数 N 含 E0000。
- **完整性校验**：各条目正文去掉空行（只含空白字符的行）后，按条目顺序以 LF 连接；结果须与"全文删去标题行和空行后以 LF 连接"的内容逐字相同。不相同则不得冻结。
- 抽样框冻结后，不得再拆分或合并条目。
- **路径、标题与主专名**：条目的路径是它各级上级标题的文字。本协议中"标题"指本条标题加路径。主专名 = 本条标题去掉行首编号（如"3.2""一、"）后的文字；协调人可在别名表中为条目另登记主专名，须在公布种子前冻结。

**标签**：在公布种子前完成，打标后不得修改。〔ED13〕
- 类别共 11 个：法则、历史、技术、母舰制度、母舰居民与地点、入侵方、本地力量、外部文明、地方世界、人物、分支。
- 每条目有 1 个主标签，副标签数量不限。本协议中凡称"带某标签"，均指主标签或副标签。
- 同时标注"主线/非主线"。
- 带"人物"标签的条目另标"主角/非主角"：文档标明主角或可操作角色的，照文档标注；文档未标明的，出现在共同开局主要行动中的人物记为主角，并在记录中注明这一依据。
- 带"母舰居民与地点"标签、描述一群居民而非一处地点的条目，另标"群体"（供 T09 使用）。
- 带"外部文明""地方世界"或"母舰制度"标签的条目，另登记"社会"字段，即该条目所描述社会的规范名（供 T06 使用）。

**别名表**：协调人在公布种子前冻结。别名表只收文本明示的等同关系（"又称""即"，或同一条目内的明确回指），并登记各条目的主专名。评委不得合并别名表以外的名称，只能标记"疑似同一"，本轮不合并。

**引用表**〔ED11〕
- **显式引用**：条目 A 的正文出现条目 B 的 ID、主专名或别名表所列 B 的别名（字符串包含），即 A 显式引用 B（A ≠ B）。
- 协调人在公布种子前机械生成有向引用表（A → B），冻结并存档。
- 用法：关联扩展（3.2）与 T12 关系用出向引用；T01 用指向该法则的入向引用；子问检索范围（2.5）用出向与入向引用。

**种子与搜索键**
- 种子为"R1|完整版本哈希"，第二轮用"R2|完整版本哈希"。R3 不重新抽样，不使用新种子〔ED26〕。完整版本哈希取 64 位小写十六进制；种子与搜索键的 SHA-256 输入一律按 UTF-8 编码，`|` 为 ASCII 竖线；公布的种子字面串存档〔ED31〕。
- 搜索键：key(用途, ID) = SHA-256(种子|用途|ID)，取十六进制串。
- 在给定用途下按搜索键升序排列，就是唯一的随机顺序。同键时按 ID 的码点顺序排列。

### 3.2 主样本（用途 = "S"）

**样本量**
- 条目总数 N ≤ 30 时，全量抽取，A—D 阶段与各项配额不运行（公式给出的 n₀ = 30 此时不再使用）〔ED26〕。
- 否则初始目标 n₀ = min(60, max(30, ⌈0.2N⌉))。所有配额按 n₀ 计算，不再重算：非主线下限 ⌈0.4n₀⌉；主标签上限 ⌊0.25n₀⌋。
- 最终样本量 n = max(n₀, A—C 阶段已选数)。60 上限只约束 n₀；A—C 阶段溢出时不删除条目，溢出优先于 60 上限，并记录"配额溢出"。

**分阶段抽取**，每一阶段都按 key("S") 顺序取条目：
- **A 类别下限**：按 3.1 类别顺序处理。对每个类别，若已选条目中带该标签的不足 min(2, 该类可用数) 条，补足。该类可用数 = 抽样框中带该标签的条目总数〔ED13〕。

- **C 非主角**：已选人物中，非主角不足 70% 时，补非主角人物，直到满足或补完为止。
- **D 补满**：补足到 n₀ 条。补入时跳过主标签已达 ⌊0.25n₀⌋ 的条目；池子取尽仍不足时，取消这一上限继续补，并记录"上限放宽"。

**冲突处理**：A—C 阶段的已选条目不删除。空类别、稀缺类别、配额无法满足，都记为"覆盖限制"，不等于作品失败（F0 另按 2.4、2.5 判断）。

**关联扩展**〔ED33〕：协调人在 S1 为每个样本条目，以及 3.3 补抽、检索补入的实例条目，沿引用表的出向引用取 min(2, 出向引用数) 条扩展条目，按 key("X", 被引条目ID) 升序，写入实例清单存档；评委不得自行增减。扩展条目用于追查证据，其中的 E1 可直接登记为有据。题目专用输入与规定检索不占这 2 条的额度。发生冲突时，以题目专用规则为准。

### 3.4 复现的含义

- 复现 = 相同的冻结抽样框（含条目切分、标签与字段）、别名表（含主专名）、引用表、阅读预算、种子与专名清单（含列表者身份），产生相同的样本、实例清单（含关联扩展与补入池）、T10 句子与检索顺序〔ED11〕。
- 标签是打标者的判断，须登记打标者身份，不是客观真相。
- 评委发现标签疑义时，登记"标签疑义"，实例照常作答。本轮不改抽样框，疑义转入下一版本处理。

## 4. 题目（★ = 不接受留白的子问）

作答格式：子问 → 状态 → 证据（等级 + 定位 + 所属层）→ 推理链 → 相关性检查。
评委不得提出新情节、谜底或数值来"修复"原稿。

- **T01 法则交叉**
  - ★该法则的约束是什么？
  - 各引用处是否遵守？（未提及该法则不算违规；没有引用条目时登记为留白，见 3.3〔ED16〕）
- **T02 突破代价**
  - ★突破是什么？
  - ★代价是什么？
  - 谁承担代价？
  - 为何不能普遍使用？
  - 具体数值属于 E0。
- **T03 入侵边界**
  - ★入侵的范围和限度是什么？
  - ★抵抗有哪些具体行动？（与 F3 共用检索，见 2.5）
  - 入侵破坏了哪些生活或补给关系？
- **T04 去留普查**
  - **决策单位**：（主体，离开或留在何处，时间点或分支节点）。同一单位的多次提及合并为一个。
  - **去重键**：(主体规范名, 去或留 + 地点规范名, 时间锚)。时间锚取文本明示的纪年或事件；没有时间时记"未定时"，主体与地点都相同的未定时单位合并为一个。别名按 3.1 别名表处理。
  - **状态**：共同开局 / 已发生 / 分支可选 / 规划或假设。
  - **动因**：主动因须是文本明示的原因；次动因不限。可选动因：灾难、选择、关系、好奇、责任、其他。同一处 E1 给出多个原因且没有主次时，记为主因集合。原因未明示时记"未明示"，该单位计入分母，不计为灾难。
  - **计算范围**：共同开局是既定前提，不计入比例；它的有限性由 T03 检查。规划或假设类也不计入。
  - **F4a 风险筛查（封顶，不是硬失败〔ED2〕）**：计数单位——非灾难单位各计 1；以灾难为唯一主因的单位，按文本明示的同一灾难事件归为一簇，每簇计 1（同一场战争中的多次撤离算一簇）。合计 ≥ 4，且灾难簇数超过合计的一半时，记"风险筛查触发"，T04 定为有条件通过。若把含灾难的并列主因也计入灾难后会越过阈值，只在报告中记"敏感"，不改变档位。合计不足 4 时不算比例，只记数量。
  - **F4b（硬失败）**：存在留下或定居单位，且它们的结局全部是毁灭或被弃。
  - **F4c（硬失败）**：★继续远行没有任何非灾难的理由（E1 或 E2）。本★子问的规定检索就是 T04 普查本身〔ED29〕：范围为 T04 词表在正文命中的全部条目，搜索名 `T04/普查/继续远行没有任何非灾难的理由`，不受 150 条目预算限制；普查读完全部命中条目即为检索完成，此时仍无非灾难理由 → ★缺失（失败事实 F4c）；普查未读完 → ★未检。
  - 非★子问：是否有留下者保持持续的生活或关系。
- **T05 母舰双重性**
  - ★这里的日常是什么？（与 F6 共用检索，见 2.5）
  - 哪项军事或航行决策会影响这里？
  - 居民能否影响决策？（没有渠道不算失败，但须与文本自洽）
- **T06 社会成因**
  - ★两个社会各自的资源条件与制度差异是什么？
  - 文本给出的差异原因是什么？
  - 专用失败条款：若全部样本社会的特征都由资源直接导出，登记为失败事实。条件不成立时按通用规则判定。
- **T07 文明内部**
  - ★存在哪些立场或个体差异？（与 F5 共用检索，见 2.5）
  - 该文明与母舰的关系依据什么：物种，还是行为与利益？
  - 检查 F5。
- **T08 谜团台账**
  - 台账为一个实例，子问"归类"〔ED35〕：逐项归类为标注留白 / 有线索可追 / 模糊无界 / 自相矛盾，每项附依据 → 有据；自相矛盾按 1.4 处理。
  - 封顶条款〔ED2〕：模糊无界超过半数 → 最高有条件通过。
- **T09 牵挂三问**（专用计数判定见 2.2 第 3 步）
  - 此人在乎什么、在乎谁？
  - 日常依赖什么？
  - 如果航线改变，此人会失去或得到什么？
- **T10 固定与可分化**
  - 5 句合为一个实例，子问"归类"〔ED35〕：每句判为固定 / 可分化 / 未标明；固定与可分化须附 E1，"未标明"不登记为缺失，只计入封顶比例，分母为实际取到的句数。
  - 检查 F7（按 2.4 的机械核对）。
  - 封顶条款〔ED2〕："未标明"超过半数 → 最高有条件通过。
- **T11 协作约束**
  - 列出在目标区域写新条目时必须遵守的约束，逐条注明来源。
  - ★至少一半约束可追溯到 E1。
  - 封顶条款〔ED2〕：遗漏 T01 的法则 → 最高有条件通过。
- **T12 关系与数值**
  - 关系逐条判为：一致 / 单向缺失 / 矛盾。
  - 数值之间只查是否互相矛盾。矛盾按 1.4 处理。
  - 单向缺失只有在影响其他题的结论时才算缺口。
  - 关系部分与数值部分各为一个非★子问〔ED17〕：全部一致、或单向缺失均不构成缺口 → 有据；存在缺口 → 缺失；出现矛盾 → 按 1.4 登记 F1 或层级未决。记"不适用"的部分不作为子问登记（见 3.3）。
- **T13 探索区分度**
  - ★两个抽中的地点，各自至少有 1 条 E1 写明的特征，并有后果；且二者之间至少存在一项后果差异。
  - 前往或停留的代价是什么？（按地点各做一项检索，搜索名 `T13/<地点条目ID>/前往或停留的代价是什么`，子问状态取两地中较差者〔ED18〕）
  - **对照步骤**：
    1. 对 A 地、B 地各做一项地点检索（2.5，范围同"子问缺失"一栏），须读完范围，列出该地全部"特征→后果"对。
    2. 对 A 的每一对，在 B 的已读范围内核对：B 未写该特征，或写了该特征但后果不同 → "差异成立"；写了相同特征且后果相同 → "同质"。
    3. 对 B 做同样的检查。
    4. 结果判定〔ED18〕，按顺序取第一条符合的：任一地点的范围因预算用尽未读完 → ★子问未检；任一地点读完后没有任何"特征→后果"对 → ★子问缺失（失败事实）；至少一项差异成立 → ★子问有据；全部同质 → 失败事实（专用失败条款）。
  - **表述限制**：结论只能写"相对于抽中的对照地点有区别"，不得写"别处没有"。

**说明**：D7、D8 只检查文本可审部分。是否恢弘、动人，交 H 轨记录，不改变 D 轨判定；实际吸引力需要原型与真人测试。

### 5.3 隔离与作废

**使用方式**
- S2 资格测试用 C01—C08。
- C09、C10 在正式作答期间作为独立的校准段单独下发，不插入世界样本，不进入事实图、分母、台账或报告正文。

**隔离对象与方式**
- 隔离对象是后续评委，不是协调者。
- 评委包只含随机编号的短文与题目模板，不含本协议第 5.2 节、第 6 节和预期判定。
- 模型评委每次都开新会话，上下文中不得包含管理员答案或本协议全文。

**作废条件**，满足任一即作废：某材料已在一轮中使用；任一评委接触过管理员包或本协议全文；材料被公开发布。作废的材料只能作练习样例。下一轮由新的材料持有人（不得是评委）撰写替换材料。

**"一轮"的含义**〔ED25〕：一轮指对同一冻结版本的一次完整评测（S0—S7）。同一次评测的 R1、R2、R3 共用同一套校准材料与变体；评测结束后，这些材料作废。

### 5.4 执行者与轨道前提

**D 轨正式前提**，缺任一项时只能做**试跑**（只输出问题清单，最终结论记为"未执行"）：
- 至少 3 个彼此隔离、资格有效的评委会话；
- 这些会话至少来自 2 个经登记的不同模型家族；
- 协调人不担任评委。

**计数单位**
- **模型家族**：同一开发机构训练的模型系列，是计数单位。
- **API 网关 / 中转服务商**：只是访问通道，不计数。两个家族经同一网关访问 → 计 2 个家族；同一家族经两个网关访问 → 计 1 个家族。

**身份登记**：每个会话登记以下字段：

```
声明家族|请求模型ID|网关|返回元数据(模型字段/响应头原文)|核验等级|验证限制说明
```

- 核验等级分三档：仅配置声明；元数据与声明一致；无法核验。
- 家族"无法核验"的会话可以担任评委，但不计入"2 个家族"的要求。
- 登记内容不构成独立性证明，报告须原样写明验证限制。

**R2**：全部换用新会话，且至少 1 个评委会话的家族不在 R1 评委的家族集合中；做不到时在报告中注明，不改变结论档位〔ED26〕（详见 5.5）。

**评委失格与资格错误的处理**
- 失格标准见 5.2。失格评委的判定仅供参考，不参与 5.5 的合并〔ED20〕；合并后才发现失格的，剔除其登记并按 5.5 重做受影响实例的合并〔ED27〕。
- 某评委在监测段出现失格级错误时：该评委本轮的世界记录降为"仅供参考"，但保留存档；重新计算有效评委数。不足 3 个时，从备用会话补足一次，备用评委须通过资格测试，并作答相同实例；仍然不足，记为"未执行"。
- 管理员答案出错时：用更正后的答案对全部评委重新评分；各评委的资格与其世界记录状态随之改变，按 5.5 重新合成；登记更正原因和撰写者身份。

**试跑可先完成的工作**（不依赖评委资源）：冻结版本与建立抽样框；抽样与实例化；校准资格测试。

**H 轨**（真人到场后执行）
- 两名真人各读 D 轨样本。
- 记录"恢弘、神秘、牵挂"的品味意见，写明理由但不打分。
- 抽查 D 轨判定的 20%〔ED24〕：抽查单位是 5.5 合并后的子问判定（两轮合计），ID 为"轮次|题号|实例ID|子问名"（实例 ID 与子问名的写法同 2.5 搜索名；T10 的归类算一个子问判定）；种子用"R1|完整版本哈希"；按 key("H", ID) 升序取前 ⌈0.2 × 总数⌉ 个。
- H 轨提出"证据定位错误"时须附 E1。协调人机械核对：成立 → 作为**D 轨记录更正**登记（原判、错误类型、E1、受影响子问），按本协议重新合成；结论若因此改变，发布"更正版结论"，并保留原版。不成立 → 记为驳回。
- H 轨的品味意见永不改变结论。所谓"不改变结论"，仅指 H 轨的意见；已核实的定位错误属于 D 轨数据修正，照常生效。

**作者自评**：同一套模板，封存；评测结束后再对比，差异大的项目列为讨论重点，不改变判定。

### 5.5 合并、分歧、复核与轮次

**实例登记的合并**（S4—S5）〔ED20〕
- 每名有效评委独立登记每个实例的子问状态、失败代码与封顶条款。失格或降为"仅供参考"的评委不参与合并。
- 全体有效评委一致的登记，直接采用。
- 不一致时，按下列顺序处理；每个实例的全部分歧与待复核项在同一次复核中一并处理，各限一次，不循环：
  1. **证据定位分歧**：协调人机械核对原句是否存在，并据此改正。改正后一致即采用。
  2. **推导或层级分歧**：交一个新的复核会话复核一次。复核会话不得是本轮评委或协调人，输入为各方的原句与推理链，输出为复核会话自己对分歧登记项的登记。复核登记与某一方一致 → 采用该方。与各方都不一致时：各方登记按 2.2 算出的实例档位都只在通过与有条件通过之间 → 该实例有条件通过（原文"取较严一档"），分歧登记项按复核登记写入台账；否则 → 该实例记为"证据不足（分歧）"，分歧登记项不写入台账〔ED27〕。该实例另有已确认的失败事实时，仍判失败（2.2 第 1 步）。
- **待复核**〔ED27〕：有以下任一情形的"通过"，即使评委一致，也须经同一次复核后定档：没有 E1；相关性检查不合格；依赖 E3；以篇幅为理由。复核会话对被质疑的登记项给出自己的登记（依赖 E3 的不得为有据）：与评委登记一致 → 通过；不一致 → 采用复核登记，按 2.2 重新定档。
- 单个评委登记的★缺失或硬失败，在合并确认前不算失败事实。

**问题台账**：每轮合并后首次确认的问题都登记，包括失败事实（硬失败代码、★缺失、已触发的专用失败条款）和非失败发现（非★缺失、层级未决）。字段如下：

```
问题ID|首次轮次|题号|条目ID|代码/子问|原句|R2核查|R3裁定|最终状态|处置(报告/修订清单)
```

"代码/子问"一栏同时注明该问题是失败事实还是非失败发现。

**R2 范围**
- 种子为"R2|版本哈希"，全部重新抽样和实例化，13 题全部重做。
- 使用新会话，且至少 1 个评委换成不同家族的模型。
- **遗留核查**：R1 中首次确认的全部问题（失败事实、★缺失、非★缺失、层级未决），由至少 1 名 R2 评委按原定位逐项核查，不论 R2 样本是否抽中这些条目。每名核查者的结果只能取：维持；撤销（须附 E1，说明属于定位错误、层级误读或作用域误读）；争议（核查者认为问题不成立，但给不出满足撤销条件的 E1）。多名核查者时〔ED30〕：全体维持 → 维持；全体撤销 → 撤销；其余情形 → 争议。核查负证据类问题（F0、★缺失、非★缺失）时，"原定位"指记录行中的搜索名、范围条目数与已读条目清单，撤销须附范围内满足条件的 E1〔ED30〕。
- **R2 首次确认的问题**〔ED21〕：已经过 R2 的合并确认，登记最终状态为"维持"，不另设核查。

**持久性**
- 冻结文本上确认的问题，是文本的属性，不是某次样本的属性。R2 没有再次抽中某条目，不影响该条目上已确认问题的效力。只有"撤销"才能取消已确认问题。

**R3（单次）**〔ED21〕
- 针对遗留核查结果为"争议"的每一个事实，失败事实与非失败发现都包括，逐事实裁定，不重新抽样。
- 由 1 个新会话执行；该会话所属模型家族须与提出、核查该事实的评委均不同，做不到时注明。
- 输入为双方的原句与推理链；对每个事实输出维持、撤销或无法裁定之一。
- R3 不投票，不扩样，不再循环。一个维度的全部争议事实裁定完毕后，再按下面的顺序合成该维度。

**跨轮维度合成**〔ED21〕：先把最终状态为"撤销"的事实从各轮记录中剔除：撤销的是子问状态类问题（★缺失、非★缺失、层级未决）时，该子问按撤销所附 E1 改登记为有据；撤销的是硬失败代码或专用失败条款时只删该事实，子问状态不变。然后按 2.2、2.3 重算受影响轮次的维度档位，再按顺序取第一条符合的：
1. 存在尚未经 R3 裁定的"争议"事实 → 先执行 R3，再从第 2 条起合成。
2. 存在最终状态为"维持"的失败事实（含 R2 首次确认的）→ **失败**。
3. 存在最终状态为"无法裁定"的失败事实 → **证据不足（不稳定）**，并在报告中逐字列出这些事实。
4. 两轮维度档位都是证据不足 → **证据不足**。
5. 否则，取不是证据不足的各轮档位中的最差档。存在持久发现（最终状态为"维持"或"无法裁定"的非失败发现）时，按有条件通过一并参与取最差档。只有一轮可用时，注明"单轮定档"。
